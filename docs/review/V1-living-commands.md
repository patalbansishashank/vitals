## Docs vs registry

`docs/COMMANDS.md`'s command table is generated from the registry (`src/commands/__tests__/docs.test.ts`, `GEN_DOCS=1` rewrites it). The test passes: the table matches the registry, with no diff. The new `serial` field is not part of the manifest, so `tool-manifest.json` and `TOOLSET_HASH` are unchanged (`parity.test.ts` and `toolManifest.test.ts` pass).

Permission-class audit: I listed every implemented write that some agent surface can reach (75 rows), with perm, impact, undo and idempotency:

- Every `plan.*` change that alters what the person is prescribed is `W·c` (staged for agents), or `destructive` (`plan.end`, `plan.replace`, refused for agents by the bus).
- `plan.swapExercise` (W) and `plan.checkIn` (W, ui+ai) only *propose* plan versions. Adopting one goes through `plan.adoptVersion` (W·c).
- `log.*` entries are `W` with retract undo, as SUITE_SPEC §1.9 specifies.
- No `read` command can write: `bufferedTx` throws on writes in read scope.

## Verified fine (pass 2 need not redo)

- Destructive commands from any agent actor return `confirmation_required` before execution. A user destructive call needs a matching, single-use confirmation token (`consumeConfirmation`).
- Staging runs only for `write` + `consequential` + agent actor. The dry-run preview restores every projection (`snapshots`). `applyPending` re-dispatches as the user `onBehalfOf` the proposer, and refuses expired and stale proposals (baseRevs).
- Rate limits: reads 20, writes 5, destructive 1 per actor turn. Users and the system are exempt.
- `today` in the command context is the app day (`appDay` with the rollover setting), not the calendar date.
- `effectiveEntries`: a retract hides its target, a supersede hides its target unless the superseding entry is itself retracted, and retract entries are never shown.
- `energyCredit`: tolerance is max(5 %, 75 kcal). The taper runs over the planned balance, and the safe side can cost at most 0.5. Behaviour with a zero or NaN target is defined. `scoreDay`: unknown items drop out of both sums, coverage < 0.4 gives no score, and assumed or paused days are never scored. `adherenceTrend`: A_7 needs 3 scored days.
- `energyNudge` only corrects an overshoot, capped at 10 % of one day, spread over the next 1–3 days, and never today.
- `adoptionPolicy` adopts automatically only when the change lowers load or is the light nudge. Anything touching a past day is rejected.
- `nextVersionNumber` skips tombstoned version ids (no collision after an undo).
- `history.undo` refuses a change that is already undone, and an agent cannot undo the person's changes.
- Commit failure rolls back the ChangeSet, removes its ledger rows, and resolves the waiting dispatch with the plain save-failed notice.
