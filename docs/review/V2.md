## Verified fine (pass 3 need not redo)

- MCP on the server: per-token rate limit, exposure (`exposedTo: 'mcp'`) and scope checks; edits are always staged (`directApply: () => false`).
- Person isolation on the server: every route resolves the person from the bearer only (`?token=` is refused). Revoke, MQTT revoke and clear-pin are scoped to the caller's person. Route patterns are strict, `PERSON_ID` is validated before any path is built, and chunk ids go through `assertChunkId`.
- Pair code check and use run in one serial section. Pairing and token files are 0600 in 0700 directories, with atomic writes. SIWC export is written `wx` 0600 and verified before the source is removed.
- Unhandled rejections on the server: every handler is caught, and 500s carry no detail.
- `serverFetch` refuses other origins and strips provider keys. Non-JSON answers end as `server_error` (or `not_vitals` while pairing).
- Correction precedence: replay, a newer device version, `clearCorrection` (the device value comes back), and correct-again plus `history.undo` (`biometrics.test.ts`).
- The redirect also covers the `bio.manual` aliases. Non-owned metrics (waist, blood pressure, VO2max) pass through. A user acting for an agent (`onBehalfOf`) on an owned stream is refused.
- `log.bulk` accepts only meal, note and steps entries, so steps is the only owned stream it can write.
- Ring views: loading, empty and error states exist. Charts are `role="img"` with a full text label; steps has a screen-reader list; the night view has a table twin.
